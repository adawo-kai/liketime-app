# LikeTime

Система учёта посещаемости учеников и расчёта зарплаты преподавателей.

Отметки посещаемости ставятся вручную или автоматически по распознаванию лиц на терминале Dahua DHI-ASI3213A-W
(сам терминал подключается последним этапом, всё остальное готово и проверяется симулятором).

## Стек

- **Backend:** Java 21, Spring Boot 3.5.16, Spring Security (JWT), Spring Data JPA / Hibernate, Flyway
- **База данных:** MySQL 8.0
- **Frontend:** React, TypeScript, Vite
- **Сборка backend:** Maven (через Maven Wrapper)

## Что умеет система

### Данные
- **Ученики, преподаватели, группы.** Состав группы хранится с историей (кто и когда вступил и вышел), поэтому
  посещаемость и зарплата за прошлое считаются по тому составу, который был тогда. Удаление мягкое.
- **Расписание.** Для группы задаются повторяющиеся занятия (день недели, время, кабинет). По ним кнопкой создаются
  занятия на нужный период; повторный запуск ничего не дублирует. Можно добавить разовое занятие, перенести, заменить
  преподавателя, отменить. Система не даёт поставить преподавателя или кабинет на два занятия одновременно.
- **Время.** Все моменты времени хранятся в UTC, расписание и периоды зарплаты считаются по Бишкеку (UTC+6).

### Посещаемость
- Журнал занятия: пришёл, опоздал, не пришёл, уважительная причина, заметка. Есть «Отметить всех пришедшими».
- Приход ученика делает занятие «Проведено». Преподаватель правит отметки только своих занятий и только недавних
  (3 дня), остальное делает администратор или менеджер.
- Источник отметки виден: «Вручную» или «Устройство» (со временем прихода). Ручная отметка важнее устройства.

### Терминал Dahua
- События принимаются по серийному номеру и ключу устройства, повторная отправка не создаёт дублей.
- Лицо на устройстве привязывается к ученику; незнакомые лица видны списком, их достаточно привязать.
- «Если похоже, то да»: событие засчитывается при уверенности не ниже порога (по умолчанию 0.8).
- Все события хранятся целиком; «Разобрать заново» пересчитывает их после привязки лица или создания занятия.
- Подробности и что нужно узнать про само устройство: [docs/dahua-integration.md](docs/dahua-integration.md).

### Зарплата
- Ставка: **сумма за один приход одного ученика на проведённое занятие** (по умолчанию 100 сом). Ставки можно
  задавать для всех, для преподавателя или для группы (самое конкретное правило побеждает), с датами действия.
- Периоды: открыт → рассчитан → утверждён → выплачен. Расчёт можно повторять, утверждённый период блокирует
  правку посещаемости и занятий за его даты. Утвердить можно только закончившийся период, у всех занятий которого есть ставка.
- Премии и удержания с обязательной причиной. Выгрузка итогов и деталей в CSV для Excel.
- Преподаватель видит свою зарплату только после утверждения периода.

### Отчёты и безопасность
- Отчёт по посещаемости учеников за период (с выгрузкой в CSV).
- Журнал действий: кто, когда и что изменил (пароли и ключи в журнал не попадают).
- 5 неудачных попыток входа подряд блокируют вход на 15 минут.
- Роли: **ADMIN** (всё, включая ставки, периоды, устройства, пользователей), **MANAGER** (работа с данными и
  просмотр зарплаты, без изменения ставок и периодов), **TEACHER** (только свои группы, занятия и зарплата).
- Секреты (пароли базы, ключи устройств, ключ подписи входа) лежат только в локальном файле настроек,
  который не попадает в git и в собранный jar.

## Сайт (frontend)

React + TypeScript + Vite, папка `frontend/`. Меню зависит от роли:

| Роль | Разделы |
|---|---|
| ADMIN | Расписание, Группы, Ученики, Преподаватели, Устройства, Зарплата, Отчёты, Кабинеты, Пользователи, Журнал действий |
| MANAGER | то же без «Пользователей» и «Журнала действий» |
| TEACHER | Мои занятия, Мои группы, Моя зарплата |

Запуск для разработки (backend должен работать на порту 8080):

```bash
cd frontend
npm install
npm run dev
```

Сайт откроется на http://localhost:5173. Запросы `/api` проксируются на backend (см. `vite.config.ts`).

## Тесты

```bash
cd backend && ./mvnw test                         # сервер, нужна MySQL с базой liketime_test
cd frontend && npm test                           # сайт
cd tools/dahua-simulator && node --test           # симулятор устройства
```

| Часть | Тестов | Что проверяют |
|---|---|---|
| Сервер | 129 | расписание, посещаемость, события устройства, зарплата, отчёты, права по ролям, защита входа, ограничения базы |
| Сайт | 81 | экраны расписания, журнала, устройств, зарплаты, меню по ролям, даты и деньги, скачивание файлов |
| Симулятор | 7 | построение событий и сценариев |

Тесты сервера идут на настоящей MySQL и откатывают свои данные. Перед выпуском приложение
дополнительно прогонялось целиком (jar в боевом профиле + симулятор устройства): от входа до расчёта зарплаты.
